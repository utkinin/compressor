# Источники и достоверность

Получены задание v1.1 (IMPLEMENTATION_BRIEF.md), исходный scaffold ZIP и пять отдельных документов, совпадающих с ZIP. Сверка и checksum — SOURCE_RECONCILIATION.md и docs/source. В исходнике есть пять UNIGY draft-семейств с числами и названием каталога; raw seed сохранён внутренне. Сам PDF, страницы каталога, supplier images, паспорта и расчётные листы не приложены. Legacy site contacts не утверждены для нового оператора ПДн.

`engineering-verified` — значение с инженерным подтверждением. В этой поставке подтверждённых характеристик оборудования нет.

`source-transcribed` — точная передача производителя с названием источника, URL/файлом и страницей. Пять числовых envelopes пришли как draft seed, без доступного PDF/страниц. Они не повышены до source-transcribed только на основании комментария исходного кода.

`draft` — непроверенная концепция/требование для уточнения. Не используется как обещанная характеристика. Equipment template выводит provenance и отделяет данные, ожидающие подтверждения. `publicProperties` не пропускает draft в фактические свойства.

Публичные family pages сохраняют пять исходных URL, показывают HTML-таблицу статусов и provenance без неподтверждённых чисел. ProductGasSpec отделён; подтверждённых записей пока нет. Типовые инженерные сценарии — не проекты. Категории компрессоров описывают принцип компоновки и перечень проверок, не гарантируют пригодность конкретного исполнения к каждому газу. Oil-Free не означает автоматически Class 0, кислородную совместимость или Ex-исполнение.

После получения каталогов: завести source record, проверить страницу и единицы, присвоить source-transcribed, получить инженерное согласование рабочей точки отдельно. Каталожный envelope не является гарантированной рабочей точкой.
