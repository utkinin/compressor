# Сверка с исходным проектом и текущими решениями

Работа началась в пустом checkout по заданию v1.1. Позднее пользователь передал исходный scaffold и спецификации, а затем изменил публичную коммерческую модель каталога. Последнее уточнение имеет приоритет над историческими family-first требованиями. Текущая реализация: [CATALOG_IMPLEMENTATION](CATALOG_IMPLEMENTATION.md); все десять прежних записей: [EQUIPMENT_MIGRATION](EQUIPMENT_MIGRATION.md).

## Что сохраняется

- Путь заказчика: задача → параметры газа → выбор компрессора → необходимая комплектация → RFQ и инженерное согласование.
- Next.js App Router, server components, минимальные client islands, строгие типы и content repository.
- Архитектура Knowledge Hub с первым кластером из шести полноценных материалов. Прежние темы проверяются на overlap и объединяются либо сохраняются во внутреннем backlog; публичные заглушки не поддерживаются. Equipment и Knowledge не дублируют одинаковый текст.
- Пять исходных очищенных draft-семейств — только внутри `src/content/internal/`, без публичных страниц по их обозначениям.
- Числовые поля, raw gas list, охлаждение, привод и source notes сохраняются как непроверенные исходные сведения. Они не повышаются до verified и не подтверждают совместимость.
- Серверная валидация RFQ, единицы, pressure reference, согласие, приватное хранение, durable delivery и режимы staging/live/preview.

## Что заменено

Публичный catalogue source of truth — утверждённая описательная таксономия: тип оборудования + назначение. Шесть equipment directions не являются искусственными Lanfor SKU. Прежние пять общих equipment categories объединены с ними по смыслу либо стали вариантами комплектации и Solutions. Пять исходных source families исключены из публичного ContentSnapshot и UI.

Все десять прежних equipment URL возвращают 404, без aliases и redirects. Это адреса ошибочной новой preview-реализации, а не исторические production URL основного сайта. Source catalogue document удалён из коллекции documents, его история осталась только во внутренней документации. В Documents сохранён один реальный опросный лист; страницы потенциальных файлов удалены. Sitemap, metadata, related content и structured data строятся только из содержательных публичных записей.

Product/ProductGroup не используются для направлений или draft source families. Подходящие CollectionPage/ItemList и breadcrumbs отражают фактический видимый каталог. Реальные подтверждённые числовые характеристики могут появиться только с evidence и согласованием; пустые пределы не заменяются вымышленными значениями.

«Система подачи азота для лазерной резки» остаётся в `/solutions/nitrogen-for-laser-cutting/`. Примеры наименований других продуктовых направлений из задания не считаются разрешением создавать неподтверждённые товары.

## Private registry и конфигуратор

`manufacturer-seed.ts` хранит очищенные исходные поля. `source-model-registry.ts` задаёт внутренние имена/алиасы и capability/source relations; `equipment-migration.ts` фиксирует миграцию. Many-to-many candidate links не являются approved selection. Публичные шаблоны и client components не импортируют registry.

Клиент вводит газ, P₁, P₂, Q и режим. Система показывает предварительный понятный тип оборудования и параметры с необходимостью инженерного подтверждения. Конкретная source model автоматически не обещается и клиенту не раскрывается.

SF₆ представлен описательным equipment intent и индивидуальным запросом без неподтверждённой модели, диапазонов или газовой совместимости. Текущий контракт RFQ использует ветку смеси с явным составом для этого контекста; это не отдельный утверждённый товарный ряд.

## Источники, очистка и права

Имена поставщиков и внутренние производственные сокращения, ранее запрещённые пользователем, не возвращаются в код, комментарии, тесты и документацию. Source-series codes разрешены текущим запросом только в private engineering data и внутреннем журнале миграции. Исходный ZIP исключён из репозитория, внешнее пользовательское вложение не является кодом проекта. Checksum в `docs/source/SHA256SUMS` относится к очищенному seed, а не к побайтной копии оригинального архива.

Каталожные PDF, страницы, паспорта, утверждённые расчёты и кейсы не предоставлены. Старые контакты не утверждены для оператора персональных данных нового сайта. Специальная чистота, Ex, oxygen-service, food/medical и другие исполнения требуют документов.

SF6RUS используется только как принцип бизнес-наименований, изложенный пользователем. Попытка внешнего чтения сайта вернула proxy 403; актуальный сайт не считается просмотренным. Старый frontend, CMS, дизайн, URL и HTML не переносятся.

## GitHub Pages

Preview остаётся отдельным статическим просмотром под `/compressor`. RFQ демонстрируется в памяти вкладки без отправки/хранения контактов; полноценный API существует только в серверной Next-сборке. Публикация подтверждается фактическим deployment и внешней HTTPS-проверкой. Старые отчёты о количестве страниц и public families — исторические; актуальная приёмка находится в [CATALOG_IMPLEMENTATION](CATALOG_IMPLEMENTATION.md).
