# Сверка с исходным проектом

Дата: 22 октября 2026 года. Сначала Git checkout был пуст и работа началась по большому заданию v1.1. Затем пользователь передал `lanfor-gas-systems-codex.zip` и пять отдельных документов. Все пять побайтно совпадают с соответствующими файлами ZIP.

Оригинальный ZIP сохранён в `docs/source/`, SHA-256 — в `docs/source/SHA256SUMS`. Оригинальные документы теперь находятся по ожидаемым путям `docs/MASTER_SPEC.md`, `CODEX_PROMPT.md`, `AUDIT_AND_DECISIONS.md`, `CONTENT_MODEL.md`, `SEO_AI.md`, `ANALYTICS.md`, `IMAGE_PLAN.md`, `MIGRATION_FROM_SF6RUS.md`, `SEMANTIC_MATRIX.csv`. Исходный AGENTS сохранён отдельно и его правила объединены с текущими. Пояснения фактической реализации отделены в IMPLEMENTED_* и IMPLEMENTATION_AUDIT.md.

## Что сверено и сохранено

- Позиционирование, 5 параметров рабочей точки, инженер/проектировщик/закупщик, SSR, минимальные client islands и repository seam совпадают.
- Пять исходных семейств UNIGY сохранены: OF2–OF8/DP, OF2–OF8/DZ, OF8–OF30/DP, OF30–OF500/DP, OF60–OF200/DP. Сохраняются исходные URL `/equipment/of…/`.
- Raw seed чисел, gas lists, названий и source notes сохранён без исправлений во внутренних данных. Тест восстанавливает исходный `products.ts` и проверяет его SHA-256. Значения намеренно не «исправлялись» по названиям семейств.
- Все пять записей были `draft` уже в исходнике. Название каталога UNIGY 2026 присутствует, но самого PDF, страниц и паспортов нет. Сайт показывает источник seed и draft-статус; raw numeric envelope, утечки и универсальная газовая совместимость не выдаются за подтверждённые свойства.
- ProductFamily и ProductGasSpec отделены. Список подтверждённых gas-specific specs пуст до получения источников. Пять инженерных категорий оборудования сохранены отдельно от пяти manufacturer families.
- Исходный knowledge intent booster-vs-source сохранён полноценной статьёй. Старые how-to-select/oil-free и solution/industry URLs получают конечные canonical aliases к соответствующим страницам. Canonical sitemap не включает aliases.
- Legacy SF₆ остаётся только в архиве/внутреннем seed и migration notes. Публичная газовая навигация его не содержит.

## Где актуальное задание расширяет seed

Задание v1.1 требует 6 газов, 14 решений, полноценные industries/cases/documents, отдельные legal pages, API RFQ с durable delivery, unit/browser acceptance и staging handoff. Эти возможности реализованы поверх архитектурных принципов seed; короткие seed placeholders не возвращались вместо готовых полезных страниц.

Editorial states используемой реализации: draft/review/approved/published по новому заданию. Все вновь написанные материалы review. Для полей используются engineering-verified/source-transcribed/draft; исходное verified сопоставляется с engineering-verified, исходные UNIGY draft остаются draft.

Исходный IMAGE_PLAN предлагал WebP-концепции, новое задание прямо разрешает собственные SVG при отсутствии подтверждённых assets. Выбраны десять согласованных SVG. Они не изображают реальные поставленные объекты.

## Что не принято как подтверждённый факт

Исходный `site.ts` содержит legacy email `info@sf6rus.ru`, телефон и краткое название юрлица. Они не являются утверждёнными реквизитами оператора ПДн этого отдельного сайта и не включены автоматически. Исходные применения без расчётов и сертификатов не превращены в обещания food/medical/ultrapure, Ex или oxygen-service пригодности.

В ZIP нет DATA_SOURCES.md и LEGAL_PD_RU.md. Текущие документы с этими именами описывают реализованные ограничения и требования к подтверждениям; не выдают себя за полученные исходники. К другим перепискам ChatGPT доступа нет: проверка выполняется по присланным файлам, коду, тестам и существующему AFARA deployment, а не по неполученной переписке.

## GitHub Pages как у AFARA

Проверены фактические README/PREVIEW.md и workflow репозитория AFARA через штатный Git-доступ. Его подход — отдельный статический просмотр без серверной обработки. Для Lanfor также подготовлен отдельный экспорт с `/compressor` basePath, сохранением страниц и явным browser-only RFQ demo. Серверный API остаётся только в полноценной Next-сборке. Публикация и проверка внешнего HTTPS считаются выполненными только после реального подтверждения, а не после локального export.
