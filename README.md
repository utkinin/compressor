Актуальная коммерческая версия: [V21_IMPLEMENTATION](docs/V21_IMPLEMENTATION.md), [сохранение контента и URL](docs/V21_CONTENT_RELOCATION.md). Публичное название описывает оборудование и назначение; исходные серии остаются только в инженерном слое.

Русский B2B-сайт подбора компрессоров и бустеров для технологических газов. Equipment — каталог оборудования по назначению, Solutions — технологические задачи, Knowledge — подробные объяснения. Next.js App Router, React, strict TypeScript, SSR-контент, типизированный файловый репозиторий и независимый от CRM RFQ API.

Основная навигация: **Оборудование · Решения · Технологические газы · База знаний · О компании · Контакты**, отдельно — **Подобрать компрессор**. Пункт «Документы» скрыт до появления реальной библиотеки. Вместо страниц предполагаемых файлов остаётся самостоятельный инструмент «Опросный лист на подбор газового компрессора» и запрос документации для выбранного исполнения на странице оборудования.

Первый кластер Базы знаний содержит шесть полноценных материалов: данные для подбора компрессора; подбор под конкретную задачу; состав комплектной системы; факторы срока службы компрессора SF₆; подбор бустера азота по давлению и расходу; газовые смеси и сложные технологические газы. Следующие темы сохраняются во внутреннем backlog с проверкой пересечения существующего контента перед созданием.

Для реальных событий Lanfor добавлены типизированная коллекция `news` и шаблон `/news/[slug]/`. Коллекция пока пуста: публичные News URL не создаются, раздел в «О компании» и отдельный пункт меню отсутствуют. ## Запуск

Нужен Node.js 24 (допустим >=22.13 <25), npm и Linux/macOS. Без БД, Docker и внешних ключей.

```bash
npm ci
cp .env.example .env.local # только если файла ещё нет
npm run dev
```

Для production-сборки в staging-режиме:

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run start
```

`RFQ_STAGING_MODE=true` означает **локальную демонстрацию**, даже при production-сборке. Используйте вымышленные контактные данные. Заявки не отправляются в CRM. `.local/` и `.env.local` исключены из Git. Настройка без перезаписи существующего `.env.local`: `bash scripts/setup.sh`.

## Приёмка

```bash
npm run test:e2e
```

Playwright проверяет production-сборку в системном Chromium, в том числе размеры 360, 390, 768 и 1440 px. При другом расположении Chromium укажите `PLAYWRIGHT_CHROMIUM_PATH`. На другой машине можно установить Chromium командой `npx playwright install chromium` и указать путь, не отключая проверку TLS или целостности загрузок.

## Коммерческий маршрут v2.1

Главная начинается с пяти понятных задач: дожатие азота после генератора; газоснабжение лазерного станка; возврат дорогого газа; CO₂ и другие технологические газы; встраивание компрессора в оборудование. Затем следуют исходные параметры, три формата поставки, газы, этапы подбора, путь до технического предложения, 4–6 статей и обращение.

Полный каталог, 19 статей, 11 отраслевых страниц и три примера расчётных задач сохраняются на прежних URL. ПЭТ и численный пример азота не публикуются без подтверждённых данных. Водород и кислород остаются в проектном рассмотрении. SF₆ представлен ссылкой на специализированное направление SF6RUS; существующий локальный адрес сохраняется как полезный справочный материал.

## Работа с RFQ

API: `POST /api/rfq`, заголовок `Idempotency-Key` (16–128 символов). Подробный запрос сохраняет JSON-контракт: газ, обе базы давления, расход, динамические параметры и отдельное согласие. Начальный запрос использует `intake: "brief"` и описание/файл, без обязательных числовых давлений и расхода. Контекст оборудования, решения или документа проверяется по публичным идентификаторам.

Файлы передаются как `multipart/form-data`: одно JSON-поле `payload` и повторяемые `files`. Разрешены PDF/JPEG/PNG/TXT, не более трёх файлов, до 5 MiB каждый и 10 MiB суммарно. Сервер ограничивает поток до разбора, проверяет формат/тип/содержимое и не доверяет одному расширению или клиентскому `accept`. Вложения остаются недоверенными документами; антивирусная проверка не заявлена.

Проверенные файлы хранятся внутри приватного envelope и передаются HTTPS-приёмнику как `attachments` с именем, media type, размером, SHA-256 и `contentBase64`. Публичные file URL не создаются. Получатель должен поддерживать этот контракт и дедупликацию ID. Лимит обращений применяется до чтения большого тела; idempotency учитывает содержимое файлов. Подробные результаты приёмки — [V21_IMPLEMENTATION](docs/V21_IMPLEMENTATION.md), тесты — `tests/rfq.test.ts` и дополнительные тесты brief/upload.

В live-режиме требуются HTTPS `SITE_URL`, утверждённый оператор и тексты ПДн, `RFQ_ENABLED=true`, `RFQ_LEGAL_APPROVED=true`, `RFQ_STAGING_MODE=false` и HTTPS доставка либо явно настроенная локальная очередь. Без них приём закрыт. Требования к размещению, локализации и обработчикам проверяет владелец до реального сбора.

CRM получает стабильный ID в payload и заголовке; получатель обязан дедуплицировать его. При прерывании процесса после удалённого приёма возможна повторная доставка с тем же ID. Для восстановления очереди в настроенной live-среде:

```bash
NODE_ENV=production npm run rfq:outbox
```

Команду следует запускать по расписанию и контролировать её код завершения/сводку. Один постоянный приватный том обязателен. Несколько независимых дисков и эфемерный serverless не поддерживаются этим файловым адаптером; для них нужно подключить общий durable store.

## Честность данных

Коммерческий каталог содержит пять собственных направлений: компрессоры для азота, бустеры азота высокого давления, компрессоры для гелия, CO₂ и других технологических газов. Существующий адрес SF₆ сохраняется как справочный вход в специализированное направление SF6RUS. Новые модели и неподтверждённые серии не создаются. Система подачи азота для лазерной резки остаётся в Solutions и имеет отдельный от дожатия азота intent.

Пять исходных source-семейств и числовые envelopes сохранены только внутри `src/content/internal/` со статусом draft. Каталожный PDF, страницы и подтверждённые расчёты не предоставлены. Совместимость не выводится из raw gas list, числовые характеристики не копируются в публичные категории. Конфигуратор формирует предварительный вариант с требованием инженерного подтверждения и не показывает source-model names.

Материалы находятся в `review`; примеры расчётных задач не названы реализованными проектами. SF₆ не предлагается как собственная коммерческая линейка Gas Systems. Staging закрыт от индексации по умолчанию. Предметные и application-изображения — оригинальные иллюстрации компоновок в WebP; процессы и редакционные объяснения — светлые SVG/HTML. Изображения не выдаются за фотографии утверждённых моделей или реализованных поставок. Действующая визуальная система: [VISUAL_SYSTEM_V2](docs/VISUAL_SYSTEM_V2.md). Registry-derived safety gate проверяет публичный контент и сборку перед публикацией.

Полная передача: [STAGING_HANDOFF](docs/STAGING_HANDOFF.md). Стартовая задача уже изолирована: используйте текущий checkout, не создавайте worktree без прямого запроса.

## GitHub Pages preview

```bash
npm run preview:build
npm run preview:test
```

Экспорт строится в изолированной копии, итог — `.local/github-pages`. Основная `.next`, исходники и `.env.local` не меняются. Для `utkinin/compressor` используется `/compressor` basePath; GitHub Pages получает только публичные HTML/CSS/JS/WebP/SVG и TXT-опросник. RFQ в preview — браузерная демонстрация: без API, CRM, хранения контактов и аналитики. Серверная staging-форма и публичное статическое preview имеют разные подтверждения.

Workflow `.github/workflows/pages.yml` собирает и публикует preview при push в текущую `work` либо ручном запуске. На GitHub источник Pages должен быть GitHub Actions. Подробности, реальный статус публикации и границы проверки — [PREVIEW](docs/PREVIEW.md).
